# 盘中盯盘 · 策略选股 · 多渠道推送

A 股盘中实时全市场扫描 → 多策略打分 → 定时汇总推送到**飞书 / 钉钉 / 企业微信 / Telegram / Bark / 自定义 Webhook**。

**和常见的「看板类」盯盘工具的区别**：它不让你看 5000 只股票，它每 5 分钟只给你 3~5 只，
并且每只都带「为什么选它」的可复核理由。

## 2. 推送渠道配置

支持 6 个渠道，**填哪个用哪个**，留空的自动跳过。可以同时推多个。

| 渠道 | 环境变量 | 获取方式 |
|---|---|---|
| 飞书 | `FEISHU_WEBHOOK` + `FEISHU_SECRET` | 群设置 → 群机器人 → 添加 → 自定义机器人 |
| 钉钉 | `DINGTALK_WEBHOOK` + `DINGTALK_SECRET` | 群设置 → 智能群助手 → 添加机器人 → 自定义 |
| 企业微信 | `WECOM_WEBHOOK` | 群设置 → 群机器人 → 添加 |
| Telegram | `TG_TOKEN` + `TG_CHAT_ID` | @BotFather 建 bot；@userinfobot 查 chat_id |
| Bark（iOS） | `BARK_URL` | App 里复制完整 URL |
| 自定义 Webhook | `CUSTOM_WEBHOOK` | 你自己的服务，收结构化 JSON |

```powershell
cd D:\code\tst-pl\intraday-feishu
Copy-Item .env.example .env
# 编辑 .env，填你想用的渠道

# 先验证配置
python run.py --test-push

# 看一眼渲染效果不发送
python run.py --test-push --dry-run
```

`--test-push` 会给每个已配置渠道发一条测试消息，并打印每个渠道的成功/失败原因。
一个渠道挂了不影响其他渠道。

**各渠道细节**：

- **飞书**：用交互式卡片（带颜色、`@所有人`、签名校验）。限 **100 条/分钟、5 条/秒**。
- **钉钉**：用 markdown 消息，支持**加签**（`DINGTALK_SECRET`）。限 **20 条/分钟**。
  安全设置也可以选「自定义关键词」，关键词填 `盘中` 或 `预警`，那样就不用 secret。
- **企业微信**：markdown 消息，内容上限 4096 字节，程序会自动截断。限 **20 条/分钟**。
- **Telegram**：`parse_mode=Markdown`，需要先跟 bot 说一句话才能收到消息。
- **Bark**：iOS 推送，纯文本，带 `level=timeSensitive` 让告警能穿透专注模式。
- **自定义 Webhook**：POST 一份结构化 JSON，字段有 `kind / title / color / text / sections / footer`，
  方便接 n8n、自建服务或再中转。

> **推送节奏**：所有渠道共享同一份消息，由 `PUSH_INTERVAL`（默认 300s）统一控制。
> 一天 4 小时 = 48 张卡片，已经是各渠道限流下的合理体感。
> 想调小前先确认你最严格的那个渠道——钉钉/企微只有 20 条/分钟。

### 加一个新渠道

在 `notify.py` 里写个类，业务代码不用动：

```python
class SlackChannel(Channel):
    type = "slack"

    @property
    def enabled(self):
        return bool(self.cfg.get("webhook"))

    def render(self, card):
        return {"text": _md(card)}      # Card → 渠道自己的格式

    def post(self, payload, url=None):
        return _http_post(self.cfg["webhook"], payload)

CHANNEL_CLASSES["slack"] = SlackChannel
```

然后 `config.CHANNELS` 里加一行 `{"type": "slack", "webhook": os.getenv("SLACK_WEBHOOK", "")}` 就完事。

业务层只产出**渠道无关**的 `Card`（`kind / title / color / sections / footer`），
各渠道自己渲染——所以加渠道永远只改推送层。

## 3. 选股策略（10 条，全部经过三重验证）

**不是拍脑袋定的。** 每条策略都用 `research.py` 跑了 6 年日线（2020-2026，967 只，
1657 个交易日）、样本外分割、**Bonferroni 多重检验校正**（15 个假设 → t 门槛 2.94），
只有全部通过的才上线。

### 验证结果（次日开盘买，T+1 超额）

| 信号 | 全样本超额 | t | 样本外超额 | 样本外 t | 执行方式 |
|---|---:|---:|---:|---:|---|
| **涨停次日** | +0.69% | **9.74** | +0.59% | 6.15 | 次日开盘买 |
| **跌停反弹** | +0.69% | **4.44** | +0.82% | 5.68 | 次日开盘买 |
| **放量十字星** | +0.34% | **5.65** | +0.34% | 3.86 | 次日开盘买 |
| **连跌首阳** | +0.28% | **5.09** | +0.36% | 5.34 | 次日开盘买 |
| **回踩反包** | +0.22% | **4.13** | +0.27% | 3.69 | 次日开盘买 |
| **低开高走** | +0.22% | **4.93** | +0.27% | 4.12 | 次日开盘买 |
| **跳空不回落** | +0.15% | **6.67** | +0.16% | 4.75 | **尾盘买 +0.45% t=15.4** |
| **站上MA20** | +0.10% | **6.99** | +0.10% | 4.72 | 次日开盘买 |
| **平台突破** | +0.03% | 1.13 | +0.04% | 1.14 | **尾盘买 +0.23% t=7.97** |
| **三连阳** | -0.03% | -2.31 | -0.01% | -0.76 | **尾盘买 +0.16% t=9.70** |

被淘汰（不准上线）：~~放量突破~~ -0.06% / ~~长下影线~~ -0.02% / ~~缩量整理~~ -0.09% /
~~新高回踩~~ 样本外转负 / ~~低开回补~~ 仅样本外显著。

> **方法自证**：放量突破作为对照组，两个口径都是 ❌。说明这套框架确实能分辨真假，
> 不是把所有东西都判成有效。

### 最重要的发现：执行方式决定盈亏

同一批信号，两种买法结果可以完全相反：

```
信号            次日开盘买          尾盘买
跳空不回落      +0.15%            +0.45%   ← 尾盘更强 3 倍
平台突破        +0.03% (不显著)    +0.23%   ← 只能尾盘买
三连阳          -0.03% (负)        +0.16%   ← 只能尾盘买
回踩反包        +0.22%            -0.23%   ← 只能次日开盘买
低开高走        +0.22%            -0.37%   ← 只能次日开盘买
涨停次日        +0.69%            -0.57%   ← 只能次日开盘买
```

原因：「日内先弱后强」的票隔夜平均低开，尾盘接货等于接在缺口上；
「高开不回补」的票隔夜继续高开，尾盘买反而多吃一段。

所以推送卡片上每条都标 `⏰次日开盘买` 或 `⏰尾盘可买`——**照做，别反过来**。

### 五层筛选漏斗

单靠技术形态不够——形态再好，公司亏损、资金在跑、大盘在崩，都不该推。所以是五层串联：

```
5571 只全市场
  ↓ ① 市场环境   指数跌破MA20 / 跌停>涨停 → 降频或暂停
  ↓ ② 基本面     无财务数据 2571 / 亏损 736 / 估值过高 449
  ↓              次新 28 / 业绩崩塌 27 / ST 17 / 负债过高 10
1619 只
  ↓ ③ 资金面     主力大额流出（>5000万且占比为负）114 只排除
  ↓ ④ 形态信号   10 条策略，要求 ≥2 个信号族共振
  1~5 只候选
  ↓ ⑤ 组合约束   同行业最多 2 只，避免一次推 5 只半导体
推送
```

实测一轮（2026-11-05 收盘后）：

```
[采集] 5571 只 / 1161ms  过筛 1619  候选 1
[过滤] 基本面 无财务数据2571，亏损736，估值过高449，次新股28，业绩崩塌27，ST/退市17，负债过高10；资金面 主力大额流出114
[环境] 中性(+0)  上证跌破MA20，创业板跌破MA20，涨跌比7.8偏多，涨停92家
```

**各层实现**：

| 层 | 文件 | 规则 |
|---|---|---|
| ① 市场环境 | `context.py` | 指数 MA20 + 涨跌家数 + 涨停跌停 → risk_on/neutral/weak/risk_off，决定推送数量（1.0 / 0.5 / 0） |
| ② 基本面 | `filters.py` | ST、上市<90天、PE≤0（亏损）、PE>100、营收同比<-30%、负债率>85%（金融股豁免） |
| ③ 资金面 | `filters.py` | 主力净流出 >5000万 且占比为负 → 排除；净占比 ≥5%/15% → 加分 |
| ④ 形态 | `strategies.py` | 10 条验证过的信号 + `MIN_FAMILIES=2` |
| ⑤ 组合 | `filters.py` | `COMB.max_per_sector=2` |

**为什么基本面是「排除器」不是「选优器」**：回测只能证明「形态有微弱优势」，
不能证明「这家公司值得买」。基本面过滤的作用是**降低踩雷概率**，不是提高收益。
一个形态再好但连续亏损的公司，不该出现在推荐里。

> 严格程度可以调：`config.py` 里的 `FUND` / `CAP` / `COMB` / `MIN_FAMILIES`。
> 现在是偏严的设置，**有些天可能一只都不推**——这是刻意的（宁缺毋滥）。

### 怎么验证新策略

```powershell
python research.py --search      # 15 个候选，Bonferroni 校正 + 样本外双门槛
python research.py --robust      # 参数稳健性：整片区域显著才算过
python research.py --corr        # 相关性：新信号和已有的会不会是同一个东西
python research.py --score-test  # 共振与评分是否真的有效
python validate.py               # 实盘 vs 回测对比
```

**没通过验证的策略不准上线。** 这是这个项目唯一的纪律。

### 已知偏差

- **幸存者偏差**：样本是当前仍存活的股票，退市股未纳入，会**高估**收益
- **日线代理**：盘中实时信号比日线更早，但也更容易假突破
- **未含冲击成本**：只扣了 0.15% 双边固定成本，大资金滑点更高
- **样本期**：2020-2026 覆盖牛熊震荡，但仍可能漏掉极端行情
- **这是数据挖掘**：10 条信号来自批量假设测试，不是从经济逻辑推导的。
  二次挖掘（看过小样本结果后才提第二批假设）没有被 Bonferroni 覆盖。

### 实盘验证（唯一能真正证明的方法）

回测再严谨也只是「历史上成立」。`validate.py` 把实盘信号和回测预期逐条对比：

```powershell
python validate.py                 # 最近 60 天
python validate.py --days 120 --min-n 30
```

输出：

```
信号          实盘n   实盘超额   回测预期    偏差     实盘胜率   判定
涨停次日        12     +0.41%    +0.69%   -0.28pp    58.3%   样本不足（需 20）
跳空不回落      31     +0.52%    +0.45%   +0.07pp    51.6%   ✅ 保留：与回测一致
回踩反包        28     -0.11%    +0.22%   -0.33pp    42.9%   ❌ 淘汰：实盘为负
```

**判定规则**：

| 条件 | 判定 |
|---|---|
| 样本 < `--min-n`（默认 20） | 样本不足，继续观察 |
| 实盘超额 ≤ 0 | ❌ 淘汰，从 `strategies.py` 删除 |
| 实盘超额 − 回测预期 < -0.5pp | ⚠ 存疑，远低于回测 |
| 其余 | ✅ 保留 |

口径与回测严格对齐：次日开盘买 → 次日收盘卖，扣 0.15% 成本，
超额 = 收益 − 当日全市场等权。

**样本从哪来**：`candidates` 表记录了每轮扫描的**全部**候选（不只推送的），
所以不受「每 5 分钟只推 5 只」的限流影响，能积累完整信号。

> 按每天 3~5 个信号估算，每条约需 **1~2 周**才能攒到 20 个样本。
> 在此之前不要相信任何回测结论。

**打分**：主因策略分 + 次因×0.25 → 多策略共振 ×1.2 → 板块共振 +10 → 封顶 100。

**推送裁剪**：单形态最多占卡片 60%（避免 5 只全是「回踩反包」），同一只股票 30 分钟内不重复推，
每日每只最多推 2 次。

## 6. 数据源与实测（双通道）

盯盘对延迟敏感，而**东财 60 页分页会触发限流**：同样代码连跑两次，一次 969ms、一次 3253ms。
所以改成双通道并行，取长补短：

| 通道 | 请求数 | 实测 | 提供 |
|---|---|---|---|
| A · 新浪全市场 | 8 批 × 800 只 | 831ms | 全市场价量、涨跌家数、涨停统计 |
| B · 东财成交额 Top3000 | 30 页 | 549ms | **量比 / 换手 / 主力净流入 / 行业** |
| 合并 | 38 个请求 | **1.1~2.3s** | 5571 只全市场 + 3000 只完整字段 |

对比原来的单通道 60 请求：延迟从「0.9~3.4s 抖动」收敛到「1.1~2.3s」，请求数降 37%，
被限流的概率大幅下降。

关键取舍：**东财只拉成交额 Top3000**。实测 Top3000 的成交额下限是 0.79 亿，
而策略门槛是 1 亿，所以**没有任何一只符合策略条件的股票会落在 Top3000 之外**——
用 30 页就够，不用拉 60 页。

### 上游会限流，这是必须处理的运维约束

实测：连续高强度请求（当天测了上千次）后，两个通道会同时劣化：

```
正常时      新浪 831ms   东财 549ms
被限流后    新浪 5155ms  东财 2799ms   ← 两通道一起慢
```

三道防线：

1. **轮询间隔 10s**（不是 2s）。策略依赖的是上游自带的 `f10`(量比) / `f22`(涨速) 字段，
   本地环形缓冲只作兜底，10s 采一轮完全够用（3 分钟涨速仍有 18 个采样点）。
   请求量比 2s 轮询降 **5 倍**。
2. **单通道 8s 超时 + 重试一次**（`FETCH_TIMEOUT`）。任一通道超时不会拖死整轮。
3. **上一轮兜底**：某通道失败时，用上一轮数据补齐**本轮完全缺失**的代码。
   只补缺失、不覆盖已有价格——避免拿陈旧价格去做止损判断。

其余实测数据：

| 项 | 值 |
|---|---|
| 东财分页并发 30 / 45 / 60 | 849ms / 527ms / **1253ms（被限流，反而变慢）** |
| 东财 ulist 批量查 5 只 | 163ms（持仓监控快查通道） |
| 全市场规模 | 5571 只有效（含停牌剔除），原始 5927 |
| 单轮完整扫描 | 采集 + 5 策略 + 打分 + 止损检查 ≈ 1.2~3.7s（限流后） |

**关键工程细节**：分页排序键必须用 `fid=f12`（代码），不能用 `fid=f3`（涨幅）。
盘中排名每秒在变，按涨幅翻页会**同时产生重复和漏项**——实测 60 页有 184 条重复/缺失，
你会漏掉正在拉升的股票。这个坑几乎所有自制盯盘工具都踩过。

### 7.2 落库

SQLite（`data/intraday.db`），四张表：

| 表 | 写什么时候 | 干什么用 |
|---|---|---|
| `candidates` | 每轮扫描，**全部候选**都写（不只推出去的） | 算覆盖率、复盘漏报 |
| `pushes` | 每次真正推送 | 去重、审计 |
| `daily` | 收盘后自动存全市场快照 + review 拉个股日 K | 算 T+N 收益 |
| `outcomes` | `review.py` 回填 | 胜率统计 |

`run.py --loop` 在 **15:00 之后自动存一次全市场收盘快照**，第二天就能算覆盖率，不用手动跑。

### 7.3 回测（不用等两周）

`backtest.py` 把 5 分钟 K 线当成「每 5 分钟一次盘中扫描」逐日重放，
复现放量突破 / 急拉 / 回踩反包三条纯价量策略。

**实测结果**（200 只成交额最大样本，2026-09-17 起 30 个交易日，458 个信号）：

```
基准线（同池同区间 次日开→收 全样本均值）= -0.20%   样本 5778 个
==============================================================================================
策略         信号数    当日剩余    次日收益    次日胜率   次日可交易      超额
----------------------------------------------------------------------------------------------
breakout       11    -0.55%      0.92%     54.5%      1.28%    +1.48%
surge         222     0.00%      0.51%     49.1%      0.97%    +1.17%
pullback      225     0.07%      0.67%     52.0%      1.16%    +1.36%
----------------------------------------------------------------------------------------------
合计          458                0.60%     50.7%
```

三个结论：

1. **有超额**：三条策略次日「开盘买→收盘卖」都跑赢基准 1.2~1.5 个点，
   不是纯吃大盘 beta（这段样本期基准是 -0.20%，偏弱市）。
2. **胜率只有 49~54%**：这是「小赢多次 + 偶尔大亏」的结构，
   **必须配止损**，否则单次大回撤吃掉全部超额。
3. **breakout 信号太少**（11 个），因为「贴日内最高 + 量比 2.5 + 换手 3~15%」三重条件
   同时满足的时点很少。想多抓就放宽 `S1.near_high`（0.995 → 0.99）。

回测不含主力资金因子（历史分钟资金流接口不通），实盘条件更严，理论上应优于回测。

```powershell
python backtest.py --stocks 400 --days 40    # 加大样本
```

### 7.4 每日工作流

```powershell
# 盘中（09:15 前启动，跑到收盘）
.\start.ps1

# 收盘后（15:00 之后）
python review.py --days 30
```

`review.py` 输出三张表：

- **A. 当日剩余收益**：信号价 → 收盘，看信号发出后当天还涨不涨
- **B. 次日表现**：信号价 → 次日收盘，看真正的持有收益
- **C. 覆盖率**：当日涨幅 3~9% 的可介入标的 Top20 里，候选池抓到了几只

> 覆盖率为什么不用「全市场涨幅 Top20」？那些基本是涨停股，而策略**主动排除已涨停**，
> 用那个口径算出来恒为 0，没有信息量。

## 8. 止损 / 止盈监控

每轮扫描后自动检查已推送的股票。复用同一份全市场快照，**零额外请求**。

### 状态机

```
pending   ──mark.py 确认买入──→  watching
watching  ──跌破 -2%──────────→  stopped   🛑 止损
watching  ──涨到 +10%──────────→  trailing  🎯 达到目标，转移动止盈
trailing  ──从峰值回撤 1.5%───→  taken     📉 移动止盈
watching/trailing ──跨日跌破 -5%──→  stopped   🛑 跨日止损
```

**关键：推送出去的票默认是 `pending`，只跟踪不告警。** 你实际买入了才用 `mark.py`
确认，确认后才开始止损告警。这样一天推 10 只只买 2 只时，另外 8 只不会制造噪音。

### 确认买入

```bash
python3 mark.py --list                    # 看今天推了哪些、还没确认
python3 mark.py 688037                    # 确认买入，成本价 = 推送价
python3 mark.py 688037 --price 222.50     # 确认买入，成本价 = 实际成交价
python3 mark.py 688037 688521             # 一次确认多只
python3 mark.py --all                     # 确认今日全部
python3 mark.py 688037 --skip             # 明确不买，移出监控
```

服务每 60 秒自动同步一次库里的确认状态，**不用重启**。

> 为什么要确认？因为止损基准是「你的成本价」。系统只知道推送时的价格，
> 不知道你 14:20 才买进、成交在 222.50。用 `--price` 回填真实成交价，
> 止损位才算得准。

### 收盘观察名单

未确认的票在收盘后自动汇总成一张「观察名单」卡片：

```
📋 收盘观察名单 16 只 · 2026-11-05
1. 芯源微 688037   🟢 +1.40%   信号价 221.39 → 收盘 224.50
   日内最低 -0.50%  最高 +1.58%  若按 -2% 止损：未触发
2. 矽电股份 301629  🔴 -2.47%   信号价 198.10 → 收盘 193.20
   日内最低 -2.90%  最高 +0.71%  若按 -2% 止损：已止损

未确认买入，只记录不告警  命中 1/3 = 33%  要纳入监控：python3 mark.py <代码>
```

这条既解决了噪音，又保留了策略验证价值——**你可以只看不买，用观察名单判断
这套策略值不值得跟**。归档后不会在第二天重复出现。

### 参数

```python
STOP_LOSS_PCT     = -2.0   # 相对信号价，跌破即告警（回测扫描得出的最优点）
TAKE_PROFIT_PCT   =  5.0   # 达到后进入移动止盈模式
TRAIL_DRAWDOWN    =  2.0   # 移动止盈：从最高点回撤多少触发
NEXT_DAY_STOP_PCT = -5.0   # 跨日持仓相对信号价跌破此值，直接判「该走了」
WATCH_ENABLED     = True
```

### 止损参数是扫出来的，不是拍的

```powershell
python backtest.py --optimize-stop
```

> 上面是 2026-11-05 13:47 快照的结果。

**四个结论**：

1. **止损不提高平均收益**（+0.51% → +0.45%，损失 0.06pp），
   它买的是尾部保护：最差单笔从 **-16.40% 砍到 -2.00%**，削减 88%。
2. **收益/尾部比值提升 7.2 倍**（0.031 → 0.223）。这个比值才是止损的真正价值——
   每承担 1 个点的最大亏损，换来的平均收益从 0.031 变成 0.223。
3. **止损会把胜率打下来**（50.1% → 28.9%）。因为大量「本来会反弹回来」的仓位被扫掉。
   这是止损的固有代价，不是参数没调好。
4. **-1% 止损比值也高（0.289）但触发率 81.8%**，几乎每笔都被扫。
   更紧的止损在实盘意味着更高摩擦成本，-2% 是收益与可执行性的平衡点。

**表 3 的结论更重要：日内平仓没有 alpha。**

```

```

所有档位都在 0 附近，最好也只有 +0.11%。**必须持有过夜**——
信号的价值在次日兑现（次日收益 +0.45%），日内平仓只是白交手续费。

**表 2（次日开盘买入，真实可成交口径）** 数字更漂亮：-4% 止损平均 +1.07%，
但注意这是「次日开盘买」，和你收到信号立刻买不是一回事，仅作参考。

> 止损按止损价成交是乐观假设，忽略跳空低开和跌停封死卖不出。实盘成交价更差。
> `breakout` 单独看最优是 -1.5%（+2.50% vs +1.80%），但只有 24 个样本，过拟合风险大，不单独设。

```
--------------------------------------------------------------------------------

3.0%          +0.49%  +0.30%  +0.20%  +0.10%  +0.11%  +0.11%   +0.45%
4.0%          +0.54%  +0.37%  +0.24%  +0.12%  +0.12%  +0.14%   +0.45%
```

**三条结论**：

1. **止盈的边际价值远小于止损。** 最好组合 +0.62% vs 纯持有 +0.45%，只多 0.17pp；
   而止损把最差单笔从 -16.4% 砍到 -2.0%。**先做好止损，止盈是次要的。**
2. **原来的 5%/2% 是最差的选择之一**（+0.29%），比什么都不做还差 0.16pp。
   原因：止盈线设太低会砍掉上涨尾部——不止损时均盈有 **6.39%**，5% 止盈直接把它腰斩。
3. **回撤越紧越好，但要看止盈线。** 10%/1% 最优（+0.62%），可 1% 回撤在实盘会被日内噪音
   反复扫（回测是 5 分钟粒度，看不到更细的波动）。取 **10%/1.5%**（+0.53%）更稳。

**分策略最优**：

```
breakout   6.0%/1.0%    +2.26%   （不止盈 +1.80%，但仅 12 个样本）
surge      4.0%/1.0%    +0.61%   （不止盈 +0.56%）
pullback   10.0%/1.0%   +0.79%   （不止盈 +0.83%，反而更差 → 不该设止盈）
```

**最终配置**：`TAKE_PROFIT_PCT = 10.0` / `TRAIL_DRAWDOWN = 1.5`。
想更简单，把 `TAKE_PROFIT_PCT` 设成 `None`，纯持有到次日收盘（+0.45%），差 0.08pp。

> 实盘有个回测测不到的因素：**人拿不住**。看到 +5% 就想跑是本能，
> 10% 的止盈线至少不会让你在 +5% 就下车。这条是心理价值，不是统计价值。

### 为什么必须要有

三条策略次日胜率只有 **49~54%**，超额 +1.2~1.5 个点。这是「小赢多次 + 偶尔大亏」的结构——
**没有止损，一次 -16% 的大回撤就吃掉全部超额**。

## 9. 已知边界

- **上游限流**：免费公开接口没有 SLA。长时间高频请求后延迟会从 0.8s 劣化到 5s+，
  极端情况下单轮可能拿不到完整数据。程序有三道防线（10s 轮询 / 8s 超时重试 / 上一轮兜底），
  但**不要拿它做需要毫秒级响应的交易**。
- **非交易时段**：`--once` 仍能跑（拿到最后快照），`--loop` 会自动休眠。
- **Level-2**：用的是 Level-1 快照，主力净流入来自东财逐笔聚合，有约 3s 延迟。
  要更细的逐笔/十档，换券商 QMT 接口，`feed.py` 换成 xtquant 即可，其余层不用动。
- **新股**：上市前 5 日无涨跌幅限制，`limit_pct` 会算错，靠 `MAX_PCT=9` 兜住。
- **止损成交假设**：回测里止损按止损价成交，忽略跳空低开和跌停封死卖不出。
  实盘成交价通常更差，真实期望低于回测数值。
- **回测样本偏差**：样本池取的是「当日成交额前 200」，天然偏向活跃股，
  所以基准线 -0.20% 不代表全市场。真实 alpha 需用实盘 `review.py` 的 B 表交叉验证。
- **不构成投资建议**：这是信息筛选工具，不是信号保证。上真钱前先用 `--once` 观察两周。
